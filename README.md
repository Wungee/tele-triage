# Alarm Triage Co-Pilot

A second set of eyes for the central monitoring unit. When a bedside monitor fires a
life-threatening arrhythmia alarm, the co-pilot checks the same things an experienced monitor tech
checks by eye, and says, with evidence drawn on the strip, whether the alarm looks real or looks
like artifact:

- Is each ECG lead readable?
- Do the two leads agree?
- Is the pulse waveform still beating?

It **never silences, delays or hides an alarm.** It reorders the queue so the likely-real alarms
get seen first, and it shows its work.

**Track:** AI/ML (Hacklanta 2026)

## The problem

In a 31-day study across five ICUs at UCSF, monitors produced over 2.5 million alarms. Of the
1.1 million arrhythmia alarms, 88% were false positives
([source](https://www.fiercehealthcare.com/it/ucsf-researchers-log-2-5-million-patient-alarms-one-month)).
Every one of them is a judgment call someone in a CMU has to make in seconds. The cost of so many
false alarms is alarm fatigue: the real one gets answered a little slower.

## What it does

- **Bed wall:** replays the minute before real ICU alarms with a monitor-style sweep. When the
  replay hits the alarm, it fires the way a central station does.
- **Ordered queue:** open alarms are sorted by the co-pilot. *Likely real* alarms go to the top
  and *likely artifact* alarms go to the bottom. Nothing is removed.
- **Evidence on the strip:** beats the co-pilot detected are marked above every channel, the
  analysed 16 seconds are shaded, and the plain-language reasons point at the channel that
  supports them (for example, "PLETH kept pulsing at 126 bpm through the asystole alarm").
- **Honest scoreboard:** after the tech makes the call, the expert annotation is revealed, and the
  app tracks how often the co-pilot and the tech matched the experts.

## How it works

1. **Signal processing** (`backend/triage/`), using only data from **before** the alarm, so it
   could run in real time:
   - two independent QRS detectors per ECG lead (ours plus GQRS); their agreement is a signal-quality index
   - pulse detection on PLETH/ABP, anchored to the patient's own pulse amplitude in the prior minute
   - alarm-specific rhythm math that mirrors the monitor definitions (longest pause, slowest 5
     beats, fastest 17 beats)
   - 89 features in total
2. **Model:** gradient-boosted trees (scikit-learn), class-balanced, trained on the PhysioNet/CinC
   2015 Challenge set (750 expert-labelled ICU alarms).
3. **Safety-first cut-off:** "likely artifact" is only shown below a probability chosen in
   cross-validation so that at most 1% of true alarms would get that label.
4. **Held-out demo:** 20% of alarms are held out. Every alarm on the demo wall comes from that set,
   and the model never trained on any of them.
5. **API:** FastAPI. **UI:** React (Vite) with canvas waveforms. **Audit log:** SQLite, or
   TimescaleDB hypertables with `time_bucket()` stats. **Summaries:** optional Gemini rephrasing of
   the evidence (it never makes the call). **Deploy:** Docker + Caddy on Vultr.

## Run it

Full step-by-step commands are in **[RUNBOOK.md](RUNBOOK.md)**. Short version:

```bash
cd backend && uv venv -p 3.12 .venv && source .venv/bin/activate && uv pip install -r requirements-dev.txt
python scripts/download_data.py && python scripts/train.py
uvicorn app.main:app --port 8000          # terminal A
cd ../frontend && npm install && npm run dev   # terminal B -> http://localhost:5173/?first=a103l
```

Production: `docker compose --profile https up -d --build`

## API

| method | path | what |
|---|---|---|
| GET | `/api/health` | model loaded, demo size, Gemini on/off, database |
| GET | `/api/model` | held-out metrics (model card) |
| GET | `/api/alarms` | demo queue (no answers included) |
| GET | `/api/alarms/{id}` | verdict, probability, reasons, vitals, waveforms + beat marks |
| POST | `/api/alarms/{id}/summary` | plain-English summary (Gemini or template) |
| POST | `/api/alarms/{id}/review` | log the tech's call, reveal the expert label |
| GET | `/api/stats` | review stats (per-minute buckets) |
| POST | `/api/score` | score any uploaded PhysioNet-format record (`.hea` + `.mat`/`.dat`) |

## Limitations

- **Research prototype, not a medical device.** Software that analyses ECG waveforms from a patient
  monitor is regulated as a device under FDA's Clinical Decision Support guidance (it fails
  Criterion 1). A real deployment would need clearance and prospective validation.
- The training data are 750 alarms from 2015-era ICU monitors. Performance on other monitors,
  units (telemetry floors vs ICU) and populations is unknown.
- Small classes: some alarm types (e.g. true V-fib) have only a handful of examples, so per-type
  numbers for them are noisy.
- No hospital data of any kind was used.
